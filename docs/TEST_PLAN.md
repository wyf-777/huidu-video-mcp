# 测试计划与发布质量门禁

> 文档状态：商业版目标测试方案；当前原型尚未具备全部测试基础设施  
> 适用对象：开发、测试、产品和发布负责人  
> 最近更新：2026-09-02

## 1. 测试目标

验证系统能够安全、稳定地把用户视频转换为相对深度视频，并确保任务队列、进度、重试、删除、计费和租户隔离符合产品约定。

## 2. 测试分层

| 层级 | 范围 | 执行时机 |
|---|---|---|
| 静态检查 | 格式、类型、依赖和密钥扫描 | 每次提交 |
| 单元测试 | 纯函数、状态机、计费和权限规则 | 每次提交 |
| 集成测试 | DB、Redis、对象存储、Celery、FFmpeg | 每次合并请求 |
| GPU测试 | 模型加载、批处理、显存和输出一致性 | GPU流水线/每日 |
| 端到端 | 上传到下载、取消、失败、删除、支付 | 候选版本 |
| 性能可靠性 | 吞吐、排队、长视频、故障注入 | 候选版本/定期 |
| 安全测试 | 鉴权、隔离、上传和依赖漏洞 | 候选版本/定期 |

## 3. 测试数据

只使用自有、已授权或合成数据。测试集至少包含：

- 1秒、10秒、1分钟和接近套餐上限的视频；
- 竖屏、横屏、方形；360p、720p、1080p；
- 24、25、30、60 fps和可变帧率；
- H.264、H.265、VP9等允许格式；有音频、无音频、多音轨；
- 快速运动、镜头切换、弱光、纯色和复杂背景；
- 文件扩展名伪装、截断文件、零字节文件、超大文件；
- 已知输出的短小黄金样本；
- 两个以上测试租户及不同套餐账户。

测试夹具应记录来源、授权、SHA-256、时长、编码、尺寸和预期结果。不得把真实用户视频加入仓库或长期测试集。

## 4. 单元测试

### 4.1 视频和参数

- 分辨率计算保持画面比例并满足编码器偶数尺寸要求。
- 输入时长、大小、帧率和像素总量上限正确执行。
- 模型、输出档位、平滑选项只接受白名单值。
- 缺失、损坏和异常元数据返回稳定错误码。

### 4.2 深度后处理

- 深度归一化处理常量数组、NaN和极端值时不会除零。
- 灰度方向符合产品约定，必要时可验证反转选项。
- 时间平滑首帧、连续帧和镜头切换行为正确。
- 同一固定输入、模型revision和随机性设置下结果处于允许误差内。

### 4.3 任务状态机

- 只允许文档定义的状态转换。
- 终态不能再次变为运行态。
- 重复创建请求通过幂等键返回同一任务。
- 取消、超时、Worker失联和重试竞争不会产生两个成功结果。
- 重试次数和错误分类符合策略。

### 4.4 额度与计费

- 创建任务时预占、成功后结算、失败/取消后释放额度。
- 重复支付回调、重复Worker回调不会重复扣费。
- 退款、赠送额度和订阅续费形成不可变流水。
- 并发创建任务不能造成余额为负。

### 4.5 权限和删除

- 用户只能查询、下载、取消和删除自己的任务。
- 管理员操作必须校验权限并写入审计日志。
- 删除请求覆盖DB状态、对象存储和缓存引用。

## 5. 集成测试

- API事务提交后才发送任务，发送失败可补偿或由outbox恢复。
- Celery重复投递不会重复扣费或覆盖有效结果。
- Redis重启后任务主状态仍能从PostgreSQL恢复。
- 对象上传完成前不能创建可运行任务。
- 签名上传/下载URL到期后失效，且限制对象键、方法和内容长度。
- ffprobe预检与FFmpeg转码错误能映射为用户可理解的错误码。
- 输出先写临时对象，校验后再变为可下载状态。
- 数据库迁移可从上一生产版本升级，并完成回滚演练。

集成测试优先使用与生产一致的容器版本，不用内存假实现替代所有外部依赖。

## 6. GPU和模型兼容测试

每一种生产GPU、驱动、CUDA、PyTorch和模型revision组合都要保存测试记录。

验证项：

- 容器能识别正确GPU，`torch.cuda.is_available()`为真；
- 模型首次加载和热加载成功；
- `torch.inference_mode()`生效，无意外梯度显存；
- FP16/BF16只在硬件与模型验证通过后启用；
- 批大小自动降级不会改变任务状态和计费；
- 连续处理至少100个短任务无持续显存增长；
- OOM能被识别、清理并按策略重试；
- CPU与GPU输出的结构和范围一致，数值差异在定义阈值内；
- 输出帧数、帧率、时长和尺寸符合预期。

黄金样本不建议逐像素完全相等；应记录容许的统计误差、结构相似度或深度排序指标，防止不同硬件浮点差异导致误报。

## 7. 端到端场景

### 正常流程

1. 注册或登录。
2. 查看额度并上传合法视频。
3. 创建任务并看到排队位置。
4. 页面刷新或重新登录后仍可看到进度。
5. 任务成功，额度结算正确。
6. 下载视频可播放，音视频时长符合约定。
7. 到期后下载失效且文件被清理。

### 异常流程

- 上传中断后续传或重新上传。
- 同一幂等键重复提交。
- 排队中取消、运行中取消和完成后删除。
- Worker进程在推理中被终止。
- Redis、数据库或对象存储短时不可用。
- 输入不支持、磁盘不足、GPU OOM和FFmpeg退出。
- 浏览器SSE断开后降级轮询并恢复进度。
- 失败任务退回额度且给出可操作提示。

### 多租户流程

使用A、B两个账号交叉替换所有任务ID、对象键和下载URL，预期始终为拒绝且不泄露对象是否存在。

## 8. 性能与容量测试

基线测试固定以下信息：GPU型号、驱动、CUDA、PyTorch、模型revision、输入规格、批大小、精度模式和编码参数。

记录：

- 模型冷启动和预热时间；
- 解码、推理、编码各阶段耗时；
- 每帧耗时和实时倍率；
- GPU利用率、峰值显存和主机内存；
- 单GPU每小时可处理视频分钟数；
- API P95/P99延迟和最大稳定并发；
- 不同队列深度下的最老任务等待时间。

建议初始验收：

- API非上传接口P95小于500毫秒；
- 进度更新间隔不超过5秒；
- 在设计负载下GPU Worker无OOM；
- 30分钟持续压测后无持续内存或临时文件增长；
- 实际产能足以在70%目标利用率内满足峰值预测。

数值应在选定生产硬件完成基线后冻结，不应把开发机GTX 1060结果作为商业SLA。

## 9. 可靠性和故障注入

- 执行中杀死Worker，确认租约到期后只恢复一次。
- Redis重启，确认API和DB事实不丢失。
- 对象存储注入超时和5xx，确认指数退避与最终失败。
- 数据库短暂只读或断连，确认不产生假成功。
- 磁盘写满，确认不损坏其他任务并清理临时数据。
- GPU返回OOM，确认批大小降级或有界失败。
- 支付回调乱序、重复和延迟，确认订单终态正确。
- 清理任务中断后恢复，确认删除最终完成。

## 10. 安全与隐私测试

- 未登录、过期令牌、伪造令牌和越权访问。
- IDOR/跨租户任务ID和对象键枚举。
- MIME、扩展名和文件魔数不一致。
- 恶意媒体导致的FFmpeg超时、资源耗尽和路径穿越尝试。
- XSS、CSRF、SQL注入、命令注入和SSRF。
- 上传、登录、任务创建和下载的速率限制。
- 签名URL最小权限、短有效期和日志脱敏。
- 依赖、容器和基础镜像漏洞扫描。
- 数据删除后对象、缩略图、缓存和搜索索引均不可访问。
- 日志中不存在访问令牌、签名URL、支付数据和原始媒体。

上线前应由未参与开发者完成一次授权边界和对象存储配置复核。

## 11. 支付与订阅测试

- 首次订阅、续费、升级、降级、取消和到期。
- 支付成功但回调延迟；回调成功但前端超时。
- 同一事件重复回调和签名错误。
- 退款、拒付和人工补偿。
- 发票/订单金额、税费、币种和套餐权益一致。
- 套餐额度不会因时区或月底边界被重复刷新。
- 不宣传“无限”而在隐藏规则中限速；所有公平使用限制在购买前可见。

生产支付测试使用支付渠道的沙箱；少量真实支付验证需有财务授权和退款闭环。

## 12. 删除和保留验证

针对一条测试任务记录其所有派生对象：输入、输出、缩略图、临时文件、缓存键、DB记录和日志引用。发起删除后验证：

- 用户立即无法访问；
- 异步删除在承诺时间内完成；
- 重试不会重新生成已删除文件；
- 备份中的残留按备份轮转周期失效；
- 必须依法保留的账务记录与媒体分离，并完成去标识化；
- 审计记录能证明何时、由谁、删除了什么类别的数据。

## 13. 缺陷等级

| 等级 | 定义 | 发布处理 |
|---|---|---|
| P0 | 数据泄露、任意代码执行、普遍错误扣费、数据不可恢复 | 阻断发布 |
| P1 | 核心流程不可用、任务重复执行、输出普遍损坏 | 阻断发布 |
| P2 | 有绕行方案的功能错误或明显性能回退 | 原则上修复，例外需书面接受 |
| P3 | 文案、轻微UI或低概率非核心问题 | 可带已知问题发布 |

## 14. 发布门禁

候选版本只有同时满足以下条件才能进入生产：

- 单元和集成测试全部通过，核心模块覆盖率达到团队约定；
- P0/P1缺陷为零；
- GPU兼容、长稳和黄金样本测试通过；
- 完整端到端、租户隔离、计费和删除测试通过；
- 性能达到基线，无超过10%的无解释回退；
- 数据库迁移、回滚和备份恢复已演练；
- 安全扫描无未接受的严重/高危问题；
- 许可证清单和上线阻断清单已签字确认；
- 测试报告记录版本、环境、证据、失败项和批准人。
