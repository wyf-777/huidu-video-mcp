# 安全、隐私与合规要求

> 文档状态：商业版上线基线；不是法律意见  
> 适用对象：产品、研发、运维、客服和管理者  
> 最近更新：2026-09-02

## 1. 数据范围

系统可能处理：

- 账号信息：手机号、邮箱、登录标识；
- 交易信息：订单、套餐、额度和支付状态；
- 用户媒体：原视频、音频、生成的深度视频和缩略图；
- 技术信息：IP、设备、请求、任务、错误和安全日志；
- 客服信息：工单、用户主动提交的诊断材料。

视频可能包含人脸、声音、儿童、住址、车牌或其他个人信息，应按高敏感度用户内容保护。系统只为提供转换服务处理媒体，不将用户视频用于训练、公开展示或人工审核，除非用户另行明确同意。

## 2. 角色与责任

- 数据负责人：批准处理目的、保留期和第三方供应商。
- 安全负责人：管理风险、漏洞和安全事件。
- 运维人员：最小权限维护生产系统，不默认查看用户内容。
- 客服人员：只能查看解决工单所必需的任务元数据。
- 开发人员：默认无生产数据库和对象存储访问权。

高权限操作使用独立管理员账号、多因素认证和完整审计，不共享账号。

## 3. 威胁模型

重点威胁包括：

- 攻击者枚举任务ID，下载其他用户的视频；
- 恶意上传利用FFmpeg、OpenCV或解码器漏洞；
- 超大或畸形媒体耗尽CPU、GPU、内存和磁盘；
- API、Worker或日志泄露签名URL与访问密钥；
- 队列重复消费导致重复扣费或覆盖结果；
- 管理员或内部人员越权查看用户内容；
- 对象存储桶、CDN缓存或备份配置错误导致公开访问；
- 支付回调伪造或重放；
- 依赖、模型仓库和容器供应链被篡改；
- 用户上传其无权使用的人物、音乐或影视内容。

新功能上线前需要说明资产、入口、信任边界、攻击方式和缓解措施。

## 4. 身份、权限与租户隔离

- 所有业务接口必须鉴权，公开健康检查不得返回内部信息。
- 服务端从令牌解析用户身份，不接受客户端传入的`user_id`作为授权依据。
- 每次任务和文件查询同时约束`resource_id`与`owner_id`。
- 对象键使用不可猜测随机值，不包含邮箱、手机号或原文件名。
- 下载通过短期、单对象、只读签名URL，默认有效期不超过15分钟。
- 上传签名限制对象键、方法、大小和内容类型，完成后仍由服务端探测。
- 后台管理采用RBAC；查看媒体属于特殊权限，并要求工单号和理由。
- 数据库、Redis、对象存储和云账号均采用最小权限服务身份。

必须用自动化测试验证水平越权、垂直越权和跨租户对象访问。

## 5. 上传与媒体处理安全

- 同时检查扩展名、MIME、文件魔数和ffprobe结果，不能只信任浏览器声明。
- 限制文件字节数、时长、分辨率、帧率、总像素、音视频流数和解码时间。
- 文件名只作为显示字段保存，磁盘和对象存储使用系统生成名称。
- 禁止把用户输入拼接到Shell命令；FFmpeg使用参数数组且禁用不必要协议。
- 解码、探测和转码在低权限隔离容器中运行，限制CPU、内存、磁盘、进程和执行时间。
- 临时目录按任务隔离，路径必须位于已验证的工作根目录。
- 默认禁止处理媒体中引用的远程URL、播放列表、脚本或外部资源。
- 依赖和基础镜像及时更新；解码组件出现高危漏洞时优先暂停相关格式。
- 病毒扫描可作为补充，不能替代格式解析隔离和资源限制。

## 6. 网络、传输与存储

- 公网流量只允许TLS 1.2或更高版本；开启HSTS和安全响应头。
- 数据库、Redis和对象存储不直接暴露公网。
- 生产网络按入口、应用、数据和GPU Worker分区，使用白名单通信。
- 静态数据使用云端或磁盘加密；密钥与数据分离管理。
- 对象存储桶禁止公共访问，启用访问日志和异常策略检测。
- 数据库备份、媒体备份和日志同样受加密与权限控制。
- 前端不得把长期云凭证、内部桶名或服务密钥发送给浏览器。

## 7. 应用安全

- 使用参数化查询和成熟ORM，禁止拼接SQL。
- 对所有输入执行长度、类型、枚举和范围校验。
- Cookie会话设置`Secure`、`HttpOnly`和合理`SameSite`；状态变更接口防CSRF。
- 用户可见文本输出前编码，配置严格CSP降低XSS风险。
- 登录、上传、创建任务、查询进度和下载均实施按用户/IP的速率限制。
- 错误响应返回稳定错误码，不暴露堆栈、绝对路径、SQL或云配置。
- 支付回调验证签名、时间戳、事件ID、金额、币种和订单归属，并保证幂等。
- API和Worker依赖持续进行SCA、镜像和密钥扫描。

## 8. 密钥与供应链

- 密钥只保存在Secret Manager，生产人员按职责临时获取。
- 不把`.env`、服务账号文件、访问令牌或私钥提交到仓库。
- 密钥轮换后验证旧密钥已失效；疑似泄露立即轮换并审查访问日志。
- 模型、依赖和容器固定版本或摘要，并保存来源、许可证和SHA-256。
- CI构建使用最小权限、短期凭证，发布制品应签名并可追溯到提交。
- 禁止在生产启动时自动执行未固定revision的远程代码。

## 9. 日志、监控与审计

日志可记录任务ID、阶段、耗时、错误码、版本和去标识化用户标识，但不得记录：

- 密码、验证码、访问令牌和Cookie；
- 完整签名URL或云密钥；
- 银行卡号、支付密码等支付敏感数据；
- 视频帧、音频内容和不必要的原文件名；
- 用户请求中未经筛选的完整Header和Body。

管理员登录、权限变更、媒体访问、数据导出、退款、人工加减额度和删除操作写入只追加审计日志。审计记录包含操作者、时间、对象、动作、理由、来源IP和结果。

## 10. 数据最小化、保留与删除

建议初始策略，正式上线前应由产品和法律顾问确认：

| 数据 | 建议保留期 | 到期动作 |
|---|---:|---|
| 未完成上传/临时切片 | 24小时以内 | 自动删除 |
| 原始输入视频 | 任务完成后24小时以内 | 自动删除 |
| 输出视频 | 7天，或套餐明确约定 | 自动删除 |
| 任务技术元数据 | 180天 | 删除或去标识化 |
| 应用日志 | 30至90天 | 轮转删除 |
| 安全审计日志 | 依法规和风险确定 | 受控归档删除 |
| 订单和财务记录 | 依法定期限 | 媒体分离、限制访问 |

- 用户可主动删除输入、输出和任务展示记录。
- 删除先立即撤销访问，再异步清理对象、缩略图、缓存和临时文件。
- 删除任务必须可重试、可审计并有完成期限。
- 备份中的数据按备份轮转自然失效；恢复备份后必须重放删除清单。
- 不得以“改名”代替删除，也不得继续用已删除内容训练模型。

## 11. 用户权利与透明度

上线前提供易读的隐私政策，至少说明：

- 收集哪些数据、为什么收集、法律依据；
- 视频由哪些基础设施和第三方处理、数据所在地区；
- 输入输出保留多久、如何删除和导出；
- 是否用于训练或人工查看；
- Cookie、分析、客服和营销用途；
- 用户如何行使访问、更正、删除、撤回同意和投诉权利；
- 未成年人政策、联系方式和政策更新方式。

产品界面不得用预选框或模糊文案取得非必要授权。将用户媒体用于案例、营销或模型训练必须另行获得明确、可撤回的同意。

## 12. 内容权利与使用规则

用户协议需要求上传者拥有或已取得以下必要权利：

- 视频和音频的复制、处理与生成权；
- 人物肖像、声音和表演的授权；
- 音乐、影视、舞蹈、商标及其他第三方素材许可；
- 涉及未成年人的监护人授权。

同时建立侵权投诉、证据保全、下架、申诉和重复侵权处理流程。不得仅用用户协议转嫁所有平台责任；具体义务应由服务地区的专业法律顾问评估。

## 13. 地区合规评估

正式收费前明确公司主体、用户所在地区、服务器地区和支付渠道，再评估适用规则。若面向中国大陆用户，重点评估个人信息保护、数据安全、网络安全、算法/生成式服务适用性、ICP备案/许可、消费者权益和电子商务要求；若面向欧盟、英国、美国或其他地区，还需分别评估当地隐私、消费者和税务规则。

深度图转换是否属于特定受监管算法服务，不能仅凭产品名称判断，应根据实际功能、内容生成方式、公开传播能力和服务对象请法律顾问给出书面结论。

## 14. 安全事件响应

1. 发现：告警、用户报告或供应商通知进入统一事件渠道。
2. 分级：确认影响的数据、租户、时间和攻击面。
3. 遏制：停用密钥、撤销URL、隔离节点、暂停上传或下载。
4. 根除：修复漏洞、清除恶意持久化、更新依赖。
5. 恢复：分阶段恢复服务并加强监控。
6. 通知：按合同和适用法律通知用户、监管方或合作方。
7. 复盘：保存时间线、根因、影响、证据和整改负责人。

安全事件证据要受访问控制，禁止在普通聊天群传播用户视频或密钥。

## 15. 上线安全门禁

- 完成数据流图、资产清单和威胁建模。
- 完成跨租户访问、上传解析和支付回调专项测试。
- 生产对象存储禁止公开访问，签名URL策略已验证。
- 密钥扫描、依赖扫描和容器扫描无未接受高危项。
- 数据保留、用户删除和备份删除重放已端到端验证。
- 隐私政策、用户协议、内容投诉和事件响应联系人已上线。
- 高权限账号启用MFA，管理员媒体访问有理由和审计。
- 至少一次独立安全复核或上线前渗透测试已完成。
