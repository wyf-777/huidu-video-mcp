# 授权与商业化检查清单

> 文档状态：商业上线前必审；不是法律意见  
> 当前结论：项目负责人已确认取得许可；正式发布前需完成授权文件归档和范围复核  
> 最近更新：2026-09-02

## 1. 当前最重要的授权结论

当前原型来自GROOVIN / Zeto分享的代码。项目负责人已于2026-09-02确认取得许可，可以按商业化方向继续开发。

在正式上线收费或分发软件前，仍需将授权原件归档，并由负责人核对以下范围：

- 是否允许修改和创建衍生代码；
- 是否允许运营收费SaaS；
- 是否允许桌面软件或源代码重新分发；
- 署名、期限、地域、用户数量和再许可要求；
- 授权方对代码及其中第三方内容是否有权授权。

授权合同或沟通原件可能包含个人和商业信息，应保存在受控法律档案；仓库只记录文件编号、审批结论、适用版本和到期提醒。最终范围仍应由专业律师结合原文件、沟通记录和服务地区审查。

## 3. 模型授权注意事项

- Small、Base和Large名称相似，不代表许可证相同，必须逐个模型仓库审查。
- 保存模型卡、LICENSE、NOTICE、revision提交号、下载日期和权重SHA-256。
- 检查许可证是否限制商业使用、托管推理、输出用途、再分发和特定地区。
- 若镜像中包含权重，属于分发场景；若启动时下载，也仍需满足来源条款。
- 开源许可证解决版权许可，不自动解决训练数据、肖像、商标、专利或输出侵权问题。
- v1只启用已完成书面审查的Depth Anything V2 Small；其余模型在UI和API均拒绝。

## 4. 软件依赖与FFmpeg

建立自动化流程生成SBOM并扫描许可证，但自动扫描结果需要人工复核：

- Python直接依赖和传递依赖；
- Node前端依赖；
- Docker基础镜像与系统包；
- CUDA、cuDNN、NVIDIA容器组件；
- FFmpeg及其编解码器构建选项；
- 字体、图标、示例视频和营销素材。

特别注意FFmpeg本体可能按LGPL或GPL条件构建，启用某些外部编解码器还会引入额外许可或专利问题。生产镜像必须记录`ffmpeg -version`输出、配置参数和发行来源。

需要履行的义务可能包括：保留版权声明、随产品提供许可证文本、提供NOTICE、标明修改、提供对应源码或允许替换动态库。具体义务以实际版本和分发方式为准。

## 6. 产品定位与收费建议

建议先把产品定位为“视频相对深度图转换工具”，避免承诺精确三维测量、医疗判断或真实空间距离。输出提示应说明：

- 结果是单目模型估计的相对深度，不是绝对距离；
- 遮挡、反射、透明物体、快速运动和镜头切换可能产生误差；
- 用户应在下游生成或制作流程中自行审核结果。

MVP收费可以按“每月包含可处理视频分钟数 + 超额包”设计。计费基准必须固定，例如按输入视频向上取整到秒后汇总，不能同时用帧数、输出时长和实际GPU耗时中对用户最不利者。

不要宣称真正“无限使用”。GPU成本随处理量增长，无限套餐容易被少数用户耗尽。若提供高阶套餐，应公开：

- 每月视频分钟额度；
- 单文件时长、大小和分辨率上限；
- 同时排队任务数；
- 优先队列等级；
- 输入和输出保留期；
- 超额价格和公平使用规则。

## 7. 单位成本模型

上线前使用生产GPU实测，不以开发机CPU或GTX 1060速度估价。

```text
单视频分钟GPU成本 = GPU每小时成本 × RTF / 60
单位完整成本 = GPU成本 + 编解码CPU + 存储 + 流量 + 支付手续费
                + 日志监控 + 客服退款 + 税费 + 预留故障成本
贡献毛利 = 实收金额 - 单位完整变动成本
```

其中`RTF = 处理秒数 / 输入视频秒数`。成本表至少按360p、720p、1080p和不同模型分别测量，并考虑：

- 平均与P95视频时长；
- GPU目标利用率不超过70%；
- 冷启动、失败、重试和空闲容量；
- 上行免费但下行收费的云流量；
- 输入、输出、临时文件和备份占用；
- 活动赠送和支付渠道退款损失。

套餐价格至少每月复盘一次实际毛利和重度用户分布。

## 9. 计费、支付与对账

- 创建任务时预占预计额度，成功后按规则结算，多余部分释放。
- 系统失败、资源失败和取消按公开规则退回额度。
- 每笔额度变化保存不可变流水，余额是流水聚合或经校验的缓存。
- 支付回调校验签名、金额、币种、订单和事件唯一ID。
- 回调、Worker完成通知和退款都必须幂等。
- 每日自动对账支付渠道订单、内部订单、退款和发票。
- 人工加减额度需要双人或分级审批，并写审计日志。
- 自动续费前、扣费后、失败时和取消后按当地规则通知用户。

用户购买前应明确展示价格、税费、自动续费、取消方式、额度有效期、失败退款和文件保留期。

## 11. 品牌与宣传边界

- 未获许可前不要使用GROOVIN、Zeto或其他主体名称暗示合作或官方关系。
- 不展示无授权的用户视频、明星肖像、影视片段和音乐作为案例。
- 不宣称“完全准确”“零失败”“无限”“永久免费”或无法证明的性能数字。
- 性能宣传注明GPU、输入规格、模型、版本和测试方法。
- “本地处理”只适用于当前单机版；云端商业版必须明确视频会上传服务器处理。
- 对AI生成和深度估计能力使用清晰、非误导描述。

## 12. 商业化阶段建议

### 阶段A：内部验证

- 保持本地原型，不收费、不公开分发。
- 确认技术效果、GPU基准和目标用户需求。
- 联系上游作者并启动许可证审查。

### 阶段B：封闭测试

- 使用自有或明确授权代码搭建队列和GPU服务。
- 只邀请签署测试条款的少量用户。
- 可发放免费额度，不接正式订阅。
- 验证失败率、单位成本、数据删除和客服流程。

### 阶段C：付费MVP

- 只提供已审查的Small模型和有限参数。
- 使用明确分钟额度，不做无限套餐。
- 启用支付、账务、退款、安全监控和公开政策。
- 设置用户数和每日处理上限，确保人工可支持。

### 阶段D：规模化

- 多GPU调度、分区队列、容量预测和灾难恢复。
- 根据实际成本扩展模型、分辨率和企业套餐。
- 定期安全审计、许可证复核和供应商评估。

## 13. 授权沟通应确认的问题

联系上游作者时，以书面形式确认：

1. 哪些代码和资源由其拥有并有权授权；
2. 是否允许修改、商业托管、按月收费和向客户提供输出；
3. 是否允许将软件或桌面包重新分发；
4. 是否允许使用名称、截图和说明材料；
5. 是否要求署名、许可证文本、收入分成或地域限制；
6. 授权期限、终止后已有用户和数据如何处理；
7. 是否包含更新、支持、保证和侵权赔偿；
8. 第三方模型、依赖和素材是否由被授权方另行负责。

口头同意和聊天中的模糊表述不足以支撑长期商业运营，最终应形成双方可验证的协议。
