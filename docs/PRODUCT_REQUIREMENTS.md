# 产品需求文档（PRD）

> 文档状态：草案，可用于MVP开发排期  
> 适用版本：商业版 v1 规划  
> 最近更新：2026-09-02

## 1. 产品定义

### 1.1 一句话描述

面向AI视频创作者的深度动作参考生成服务：用户上传普通视频，系统生成稳定、可下载并适配主流AI视频平台的深度图视频。

### 1.2 产品目标

- 将“安装Python、模型和依赖”的技术流程变成普通用户可完成的网页操作。
- 在可预测的时间内稳定完成视频深度转换。
- 用排队、额度、任务恢复和清晰错误提示支撑付费用户。
- 保护用户上传内容，建立可执行的数据删除和版权规则。

### 1.3 非目标

商业版 v1 不负责：

- 直接生成 Seedance、Kling 或 Hailuo 的最终视频。
- 绕过第三方平台的版权、安全或内容审核。
- 承诺动作百分之百还原。
- 提供无限时长、无限分辨率或无限并发。
- 保存用户视频作为公共素材库。

## 2. 目标用户

### 2.1 核心用户

- AI舞蹈与角色短视频创作者。
- MCN和短视频工作室。
- 需要动作参考的动画、广告和虚拟人团队。
- 不熟悉Python、CUDA和命令行的个人创作者。

### 2.2 典型任务

- 把15秒舞蹈视频转换为720p深度视频。
- 批量处理多个动作片段。
- 查看排队位置和处理进度。
- 转换失败后了解原因并安全重试。
- 下载结果后将其用作第三方AI视频平台的动作参考。

## 3. 产品边界与假设

- MVP优先支持 MP4、MOV 和 WebM。
- 默认单段时长上限为60秒；针对外部平台可提供15秒自动切片。
- 默认使用 Depth Anything V2 Small。
- 付费按“处理视频分钟数”计量，不采用真正无限套餐。
- 首发语言为简体中文。
- 首发形态为Web服务；本地桌面版保留为内部工具和高级用户选项。
- 品牌名称、域名、价格和公司主体尚未确定，文档中不做最终承诺。

## 4. 用户流程

```text
注册/登录
  → 查看剩余额度
  → 上传视频
  → 系统预检
  → 选择模型与输出参数
  → 创建任务
  → 排队
  → GPU处理
  → 编码与保存
  → 下载结果
  → 到期自动删除输入和输出
```

## 5. 功能需求

### 5.1 账户与套餐

| 编号 | 需求 | MVP验收 |
|---|---|---|
| ACC-01 | 支持手机号或邮箱登录 | 用户可以登录、退出和找回访问权限 |
| ACC-02 | 显示套餐与剩余额度 | 创建任务前可以看到可用分钟数 |
| ACC-03 | 记录额度扣减明细 | 每次扣减可追溯到唯一任务 |
| ACC-04 | 失败任务自动退还额度 | 非用户原因失败时自动回补 |

### 5.2 上传与预检

| 编号 | 需求 | MVP验收 |
|---|---|---|
| UP-01 | 支持拖放和文件选择 | 支持名单内格式可以完成上传 |
| UP-02 | 校验扩展名、MIME和文件头 | 仅改扩展名的非法文件会被拒绝 |
| UP-03 | 读取时长、帧率和分辨率 | 创建任务前展示检测结果 |
| UP-04 | 限制大小、时长和分辨率 | 超限时在上传前给出明确提示 |
| UP-05 | 支持取消上传 | 取消后删除未完成分片 |

### 5.3 深度转换

| 编号 | 需求 | MVP验收 |
|---|---|---|
| CVT-01 | 支持Small模型 | 输出帧数、帧率和比例正确 |
| CVT-02 | 支持360p、720p和原尺寸 | 不放大低分辨率输入 |
| CVT-03 | 支持黑白反转 | 输出深度方向符合选择 |
| CVT-04 | 支持时间平滑 | 相同输入可开启或关闭该功能 |
| CVT-05 | 支持可选音频保留 | 有音轨时正确复制，无音轨时不失败 |
| CVT-06 | 支持15秒自动切片 | 切片顺序、时长和命名可预测 |
| CVT-07 | 失败不覆盖原文件 | 原始输入始终保持不变 |

### 5.4 队列、进度与任务恢复

| 编号 | 需求 | MVP验收 |
|---|---|---|
| JOB-01 | 创建任务后返回唯一 `job_id` | 重复请求可以通过幂等键去重 |
| JOB-02 | 显示排队位置 | 队列变化后页面自动更新 |
| JOB-03 | 显示阶段和百分比 | 刷新页面后仍能恢复进度 |
| JOB-04 | 支持取消排队任务 | 未开始任务可立即取消 |
| JOB-05 | 支持取消运行任务 | 工作进程在安全检查点终止 |
| JOB-06 | 支持结果历史 | 在保留期内可重新下载 |

### 5.5 下载与删除

| 编号 | 需求 | MVP验收 |
|---|---|---|
| OUT-01 | 结果使用受控下载地址 | 地址短期有效且不可枚举 |
| OUT-02 | 用户可主动删除任务 | 输入、输出和派生文件均被删除 |
| OUT-03 | 到期自动删除 | 删除任务有日志和可审计结果 |
| OUT-04 | 文件名安全 | 不使用用户路径作为服务器路径 |

### 5.6 管理后台

- 查看队列长度、运行中任务和失败率。
- 按任务ID查询日志，不直接显示用户视频内容。
- 暂停新任务、禁用异常账户和重新入队可重试任务。
- 查看GPU利用率、显存、温度和每分钟处理成本。
- 配置套餐额度、文件限制和数据保留期。

## 6. 非功能需求

### 6.1 性能目标

下列指标需在确定生产GPU后通过基准测试冻结：

- 任务创建接口 P95 小于500毫秒，不含文件上传。
- 进度数据更新延迟小于3秒。
- 任务状态查询可用性不低于99.9%。
- 成功任务输出帧数与输入帧数一致，允许显式切片场景例外。
- 单GPU并发默认1；通过单任务帧批处理提升利用率。
- 首个商业里程碑要求720p Small模型处理速度达到“低于或等于视频时长的2倍”，最终指标以实测成本为准。

### 6.2 可靠性目标

- 服务重启后，排队和运行任务不会无记录丢失。
- 可重试失败最多自动重试3次。
- 非可重试错误不进入循环重试。
- 任务状态转换必须可审计。
- 输出文件通过可读性、帧数和时长检查后才能标记成功。

### 6.3 安全与隐私目标

- 上传和下载仅通过HTTPS。
- 对象存储默认私有。
- 输入、输出和日志采用不同保留策略。
- 用户可主动删除自己的数据。
- 日志不记录原始文件内容、访问令牌和支付信息。
- 管理员访问必须启用多因素认证和审计日志。

## 7. 错误体验

用户错误必须采用“原因 + 可执行建议”的格式：

- `VIDEO_UNSUPPORTED`：无法读取此视频，请转换为 H.264 MP4 后重试。
- `VIDEO_TOO_LONG`：视频超过当前套餐的时长限制。
- `QUEUE_FULL`：任务较多，请稍后重试；不扣除额度。
- `GPU_OOM`：当前分辨率超出资源，请降低分辨率后重试。
- `PROCESSING_TIMEOUT`：处理超时，额度已退还。
- `OUTPUT_INVALID`：输出校验失败，系统将自动重试。

页面不得只显示“错误”两个字，也不得向普通用户暴露服务器路径和完整堆栈。

## 8. 计费原则

- 计量单位：输入视频秒数，按套餐规则向上取整。
- 创建任务时预占额度；任务成功后结算。
- 用户原因导致的格式或超限错误不扣费。
- 系统错误、超时和最终失败自动释放额度。
- 重试属于同一任务，不重复收费。
- 所有额度变更必须记录不可变流水。

## 9. MVP发布验收

满足以下条件才可以邀请外部付费用户：

- Small模型GPU推理通过功能和性能测试。
- 队列、任务恢复、取消和分类重试完成。
- 支付回调具备幂等处理和对账记录。
- 用户可以查看、下载和删除自己的任务。
- 数据自动删除已通过演练。
- 隐私政策、用户协议和版权投诉流程已上线。
- 上游代码和模型商业授权完成书面审查。
- 监控、告警、备份和回滚经过一次演练。

## 10. 路线图

### 阶段A：本地技术验证

- 建立独立GPU环境。
- 加入 `torch.inference_mode()`、AMP和帧批处理。
- 完成同一视频CPU/GPU基准对比。

### 阶段B：单GPU内测

- FastAPI、Redis、Celery、PostgreSQL和对象存储。
- 单GPU单工作进程。
- 任务状态、持久化进度和可控重试。

### 阶段C：小规模付费

- 账户、套餐、支付、额度和管理后台。
- 多GPU路由、成本监控和自动扩缩容。
- 安全、隐私、内容权利和运营流程上线。

### 阶段D：产品扩展

- 姿态图、分割图和镜头稳定。
- 批量任务、工作区和团队协作。
- 第三方AI视频平台预设和自动化工作流。
